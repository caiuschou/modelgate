## 一、目的与读者

本文描述 **以会话（session）为主线** 优化控制台「请求审计日志」体验的产品与技术方案，包括：与现有「经典列表」的关系、数据语义、分期交付与开放问题。

**读者:** 产品、前端、后端。第八节给出前后端实现要点；**具体路径、字段名与类型** 以 [开发 API](../../development/api.md) 与仓库实现为准。

---

## 二、背景与目标

### 2.1 背景

- 审计表以 **单次请求** 为粒度存储，每条记录可有可选字段 **`thread_id`**（与请求头 `X-Thread-Id` 对应），表示调用方会话。
- **同一会话多次请求** 会产生 **多行相同 `thread_id`**，在「按时间平铺」的表格中，会话列重复出现，不利于快速理解「同一会话下有哪些请求」。
- 团队希望在不强制引入外部可观测平台（如独立 Trace 后端）的前提下，让控制台侧 **更好串联 LLM 相关请求与会话**。

### 2.2 目标

| 维度 | 目标 |
|------|------|
| **可理解** | 用户能按 **会话** 理解多条请求之间的关系，减少在表格中扫重复会话 ID 的认知负担。 |
| **可排查** | 仍能从任一条请求进入 **单条详情**（请求体、响应体、用量等），与现有能力兼容。 |
| **可演进** | 方案分期交付；后端分页与总数语义正确；不混淆「会话实体」与「请求审计行」。 |

### 2.3 非目标（本期默认不做）

- 不替代专业分布式追踪后端；不在此方案中承诺完整 OpenTelemetry 全链路落地。
- 不改变「**一次 API 调用对应一条审计行**」的核心存储模型（除非另立项目做会话汇总表，见第三节 3.3）。

## 三、概念与数据语义

### 3.1 三个层次（用语对齐）

| 概念 | 含义 | 与现有字段的关系 |
|------|------|------------------|
| **请求（Request）** | 网关记录的一次调用 | 一行审计；主键为 **`request_id`** |
| **会话（Session）** | 调用方标识的一段连续交互 | 可选 **`thread_id`**；多条请求可共享同一 `thread_id` |
| **追踪（Trace）** | 更广义的「一次用户旅程」的可观测关联 | 可用 `request_id`、未来可扩展 `trace_id`；本方案以 **会话 + 请求** 为主 |

### 3.2 「重复」的两种含义（必须区分）

1. **展示重复**  
   同一会话下多行都显示同一串 `thread_id` —— 属于 **UI 问题**，通过 **分组 / 主从布局** 解决，**不要求** 数据库里每个 `thread_id` 只存一行审计。

2. **数据重复**  
   同一 **`request_id`** 被插入两次 —— 属于 **幂等与重复写入** 问题，由 **请求级去重** 策略解决，与会话无关。

### 3.3 写入侧「会话去重」的合理含义

- **不推荐** 在审计表中实现「每个 `thread_id` 仅保留一行」—— 会丢失请求级历史。
- **推荐**：
  - **规范化**：写入前对 `X-Thread-Id` 做 trim 等处理（已有则保持），必要时增加长度上限、Unicode 规范化等，避免「同一语义、不同写法」被当成不同会话。
  - **可选**：维护独立 **会话维表**（`thread_id` 唯一），审计行引用其 ID；**会话表** 不重复，**审计行** 仍多条。
  - **请求幂等**：同一 `request_id` 不重复插入。

## 四、与「经典列表」的关系

| 路径 | 定位 |
|------|------|
| **`/logs`** | **经典列表**：平铺所有符合条件的请求，列顺序以「请求标识」优先，适合习惯表格排查的用户。 |
| **`/logs/v2`** | **新版列表（会话优先）**：在相同筛选与数据源前提下，强调 **会话维度** 的浏览方式（列顺序、分组、主从等按分期实现）。 |

两版本通过 **显式入口** 切换（如「经典列表 / 新版列表」），切换时 **保留当前查询参数**（时间范围、筛选等），避免用户重复操作。

## 五、UI 布局

本节描述 **`/logs/v2`（会话优先）** 的目标布局；**`/logs` 经典列表** 仍以 [日志中心 UI/交互规格](log-center.md) 为准。实现可分阶段：先 **全宽列表 + 分组**，再 **主从分栏**。

### 5.1 桌面端 — 全宽列表（分期早期）

筛选区与经典列表一致；主区域为 **按会话分组** 的可滚动列表（或分组表格）。无右侧详情时，行级操作仍通过 **「详情」链至全页** `/logs/:requestId`。

```
┌────────────────────────────────────────────────────────────────────────────┐
│  标题：日志中心（新版） · 说明文案 · [刷新] [导出] [经典列表]                    │
├────────────────────────────────────────────────────────────────────────────┤
│  筛选区（时间范围 · 快捷范围 · 关键词 · 模型 · [更多条件] · [查询] [重置]）        │
│  （已应用条件 chips）                                                       │
├────────────────────────────────────────────────────────────────────────────┤
│  ▼ 会话 abc123…  （3 条）                              最近活动 · 可选汇总        │
│      │ 时间 · 模型 · 状态 · 用量 · 耗时 · [详情]                               │
│      │ 时间 · 模型 · 状态 · 用量 · 耗时 · [详情]                               │
│      └ 时间 · 模型 · 状态 · 用量 · 耗时 · [详情]   ← 组内行可不重复展示 thread 列 │
│  ▼ 会话 def456…  （1 条）                                                    │
│      └ …                                                                     │
│  ▶ 无会话  （0 条时整块不展示；有则单独一组，若产品允许展示无 thread 请求）         │
├────────────────────────────────────────────────────────────────────────────┤
│  分页：共 N 条 · 上一页 / 下一页                                              │
└────────────────────────────────────────────────────────────────────────────┘
```

**要点：**

- **组头**：展示会话标识（可截断 + Tooltip 全文）、组内请求条数；可选展示组内最近时间或简单汇总（产品定）。
- **组内行**：突出单次请求维度字段；**会话 ID 仅在组头出现**，避免列级重复（与第三节 3.2「展示重复」一致）。
- **折叠**：默认展开全部组，或仅展开首组；需记忆用户偏好时可后续迭代。

### 5.2 桌面端 — 主从分栏（分期第二期）

在 5.1 基础上，主区域 **左右分栏**：左侧为 **分组列表（较窄，约 40%～55% 宽）**；右侧为 **详情面板（较宽）**。未选中行时，右侧显示 **占位说明**（「请选择一条请求」）；选中后加载该 **`request_id`** 对应详情，结构与全页详情对齐。

```
┌────────────────────────────────────────────────────────────────────────────┐
│  标题与筛选区（同 5.1，横跨整行）                                              │
├──────────────────────────────────┬─────────────────────────────────────────┤
│  分组列表（可滚动）                 │  详情面板（可滚动）                       │
│  ▼ 会话 abc…                      │  摘要 · 元数据 · 请求体 · 响应体 …       │
│     ● 行 1 选中                    │  （与 /logs/:id 信息架构一致）            │
│       行 2                         │  [在新标签打开完整页] 可选                 │
│  ▶ 会话 def…                     │                                         │
├──────────────────────────────────┴─────────────────────────────────────────┤
│  分页（作用于左侧列表数据集；与全宽模式一致）                                  │
└────────────────────────────────────────────────────────────────────────────┘
```

**要点：**

- **分隔**：中间可采用 **可拖拽分隔条**（可选），便于大屏阅读长 JSON。
- **选中态**：列表行 **高亮**；切换行时右侧 **替换内容**，并显示加载态。
- **深链**：保留 **全页详情** 入口（链接或按钮），避免仅依赖侧栏导致无法分享。

### 5.3 窄屏与触控

主从左右分栏 **不适用** 时，采用 **单栏列表 + 覆盖层**：

- 点击某行 → **自底部滑入面板** 或 **全屏层** 展示详情；**返回** 回到列表。
- 筛选区可 **折叠** 为顶栏按钮「筛选」，以腾出纵向空间。

```
┌──────────────────────────┐
│  标题 · [筛选] [···]      │
├──────────────────────────┤
│  分组列表（同逻辑）        │
│  ▼ 会话 …                 │
│     行 …                  │
├──────────────────────────┤
│  分页                     │
└──────────────────────────┘
        ↓ 点击行
┌──────────────────────────┐
│  [← 返回]  请求详情       │
│  （详情内容区，可滚动）     │
└──────────────────────────┘
```

### 5.4 与全局导航的关系

- **侧栏「日志中心」** 默认进入 **`/logs`**（经典）或按产品统一改为新版入口；若两版并存，侧栏只保留 **一个主入口**，另一入口由列表页 **切换按钮** 承担（与当前产品约定一致时可不改侧栏）。
- **面包屑**：新版可在「日志中心」下增加 **「会话视图」** 或沿用「请求日志」文案，避免与 [日志中心 UI/交互规格](log-center.md) 冲突，具体以信息架构评审为准。

## 六、能力分期（建议）

### 6.1 已实现（基线）

- 新版路由与页面壳；与经典列表 **共用** 审计列表接口与筛选模型。
- 表格 **列顺序** 上将会话列提前，突出「按会话阅读」；标题与说明文案区分新版。

### 6.2 第一期（会话可见性）

- **列表仅展示「有会话」的请求**（`thread_id` 非空且规范化后非空）：应在 **服务端查询** 中过滤，以保证 **总数与分页** 与展示一致；新版列表默认启用，经典列表保持「全部请求」除非产品另有规定。
- **按会话分组展示**：组头展示会话标识与组内条数；组内行可 **不再重复展示** 完整 `thread_id` 列，或弱化显示，避免「展示重复」。

### 6.3 第二期（主从详情）

- **主从布局**：点击列表行在 **右侧（桌面）** 打开详情；窄屏用全屏层或底部抽屉承载 **同一套详情内容**。
- **独立详情页**（`/logs/:requestId`）保留，用于深链、新标签打开与现有习惯；主从区域与全页 **复用同一套信息结构**。
- **可选**：URL 查询参数记录当前选中 `request_id`，支持刷新恢复。

### 6.4 第三期（演示与运营）

- **演示数据模式**（如查询参数或开关）：使用前端或后端约定的 **演示数据集**，**显著标注** 为演示；导出等高风险操作在演示态 **禁用或二次确认**。

### 6.5 远期（可选）

- 会话级 **聚合列表**（每会话一行 + 展开请求列表）；需 **聚合 API** 或明确聚合规则。
- 与 **LLM Trace** 字段（如 `trace_id`）对齐及日志关联，在独立专题中展开。

## 七、列表与筛选规则（原则）

- **时间、模型、状态等** 与经典列表一致，避免两套语义。
- **「仅存在会话」** 作为 **筛选条件** 时，必须由 **后端** 在 SQL/查询层约束，而非仅前端过滤当前页数据。
- **导出**：导出范围与时间与产品定义一致；若导出不含部分筛选条件，须在界面 **明确提示**（与现有行为一致）。

## 八、前后端技术方案

本节描述 **会话优先列表** 落地时的前后端分工与实现要点；**具体路径、字段名、类型** 以 [开发 API](../../development/api.md) 与源码为准，变更时同步本文。

### 8.1 后端

| 主题 | 方案要点 |
|------|----------|
| **列表查询** | 在现有「审计请求列表」查询上增加 **布尔开关**（例如「仅包含有会话的行」）：为真时，在 **同一套 WHERE** 中增加对 `thread_id` 的约束（非空且去首尾空白后非空），保证 **列表 SQL 与 COUNT 合计** 使用相同谓词，分页与 `total` 一致。 |
| **与精确筛选的关系** | 若请求中同时带有 **按某字符串精确匹配 `thread_id`** 与「仅含会话」，二者为 **AND** 关系；仅前者时行为与现网一致。 |
| **分析 / rollup** | 若小时聚合等优化路径与列表 **共用查询结构体**，新增条件后应使该路径 **自动回退到明细扫描** 或 **显式标记不可走 rollup**，避免统计与列表不一致。 |
| **写入路径** | 网关在持久化审计行前，对 `X-Thread-Id` 做 **规范化**（至少 trim；长度上限、Unicode 正规化等以产品为准），与 [审计技术方案](../../architecture/audit-log-technical-solution.md) 及代理实现一致。 |
| **幂等** | 同一 `request_id` 重复写入的策略维持现有设计；**不在** 会话层做「每个 `thread_id` 只插一行审计」。 |
| **鉴权与范围** | 列表与详情仍经 **控制台会话** 与 **团队 / 个人** 数据范围校验，与现网一致；无新增公开接口。 |
| **远期：按会话聚合** | 若产品需要「每会话一行」列表，需 **独立查询**（例如按 `thread_id` 分组聚合 + 子查询或专用 API），与「请求级列表」分流，避免在应用层对全表扫描冒充分页。 |

### 8.2 前端

| 主题 | 方案要点 |
|------|----------|
| **路由与入口** | ` /logs/v2` 使用 **独立页面或布局变体**；与 ` /logs` **共用** 筛选状态机（URL 查询参数），切换版本时 **保留** 与版本无关的筛选项。 |
| **列表数据** | 使用与经典列表 **同一套列表请求封装**；在 **仅新版** 场景为请求增加「仅含会话」对应 **查询参数**，使后端完成过滤，**禁止** 仅在前端对当前页数组 filter 冒充「仅会话」（避免 `total` 与翻页错误）。 |
| **分组 UI** | 在 **客户端** 对当前页返回的 `data` 按 `thread_id` **分组**（稳定排序：组间顺序、组内时间顺序由产品定）。注意 **跨页同会话** 可能分段出现，属已知限制，除非后端提供按会话分页。 |
| **主从详情** | 右侧（或叠层）详情使用与 **`/logs/:requestId`** **相同的数据获取逻辑**（摘要 + body 分块加载等），抽 **可复用容器组件**，避免两套详情实现分叉。 |
| **选中与 URL** | 可选：用查询参数（如选中 `request_id`）驱动 **初始选中** 与 **刷新恢复**；与路由守卫、登录重定向兼容。 |
| **演示模式** | 若启用：使用 **独立 queryKey / 静态数据** 或 Mock，界面 **显著标注**；导出按钮在演示态 **禁用或二次确认**。 |
| **测试** | 列表与切换：补充 **单元测试**（分组纯函数、URL 与 query 构建）；关键路径 **Playwright** 覆盖（参见仓库 `AGENTS.md` 与 E2E 约定）。 |

### 8.3 联调与验收关注点

- 新版列表在开启「仅含会话」时，**总条数 + 翻页** 与数据库抽样一致。  
- 经典列表 **默认** 不带该限制时行为与升级前一致。  
- 分组视图下列数与当前页 **接口返回条数** 一致（无静默丢弃）。  
- 详情侧栏与全页详情对同一 `request_id` **展示内容一致**（除布局差异外）。

## 九、交互与无障碍（原则）

- 分组头支持 **展开 / 折叠**；键盘与屏幕阅读器可感知 **当前选中行** 与 **详情面板**。
- 详情异步加载时展示 **加载态**；失败时 **错误范围限定在详情区域** 并提供重试。
- 大文本响应体沿用 **虚拟滚动** 等策略，避免主从布局下卡顿。

## 十、风险与开放问题

| 项 | 说明 |
|----|------|
| **分页与分组** | 仅对「当前页」分组时，同一会话可能跨页断裂；是否接受、是否需「按会话分页」接口，需产品确认。 |
| **无会话请求** | 新版若默认「仅有会话」，无 `thread_id` 的请求不可见；需明确是否提供「显示全部」开关。 |
| **多团队 / 权限** | 会话列表与详情必须在现有 **控制台鉴权与团队范围** 内一致，避免越权。 |
| **隐私** | 详情面板若展示请求/响应体，与现有一致，遵循脱敏与权限策略。 |
