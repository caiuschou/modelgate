# 充值与计费 — UI/交互规格

**版本:** 1.0  
**日期:** 2026年4月  
**关联需求:** [充值与 LLM 调用扣费（产品方案）](../../product/recharge-and-billing-solution.md) · [导航设计](navigation.md) · [设计概述 — 信息架构](overview.md) · [日志中心 UI/交互规格](log-center.md)

> **计价货币：** 界面展示金额均为 **USD**，格式见本文 §6；与产品方案一致。  
> **实现状态：** 控制台路由以 [导航设计 — 当前控制台实现](navigation.md) 与 [实现状态](../../implementation-status.md) 为准；本文描述目标态交互，未落地前可作为验收清单。

## 一、范围与分期

| 分期 | 内容 | 说明 |
|------|------|------|
| **P0** | 充值中心入口、账户余额展示、在线充值主路径、充值记录列表、消费流水列表 | 与预付费闭环一致；支付跳转以实际对接渠道为准 |
| **P1** | 流水/账单导出（CSV）、首页余额卡片与低余额提示条、消费行跳转审计日志详情 | 与 [日志中心](log-center.md) 联动 |
| **预留** | 发票/invoice 下载、赠送金分账展示、多币种支付展示（非 USD） | 产品方案 V2+ |

## 二、路由与信息架构

### 2.1 路由（建议）

| 路径 | 页面 | 鉴权 |
|------|------|------|
| `/billing` | 充值中心（默认子页：在线充值） | 需登录 |
| `/billing/top-up` | 在线充值（可与 `/billing` 同页 Tab，则本路径为锚点或重定向） | 需登录 |
| `/billing/usage` | 消费流水 | 需登录 |
| `/billing/deposits` | 充值记录 | 需登录 |

**简化方案（MVP）：** 仅使用 **`/billing` 单页**，内部用 **Tab** 切换「在线充值 / 消费记录 / 充值记录」，不拆子路径；若拆子路径，Tab 与 URL 同步（`?tab=` 或上述 segment）。

### 2.2 充值中心内信息架构

```
充值中心 (/billing)
├── [Tab] 在线充值          ← P0；默认选中
├── [Tab] 消费记录          ← P0；按调用扣费流水
└── [Tab] 充值记录          ← P0；按支付入账流水
```

与 [设计概述 — 信息架构](overview.md) 中「充值中心」对齐时，将原「余额查询」并入 **顶栏摘要区**（见 §4.1），将「在线充值 / 充值记录」扩展为上述三 Tab。

### 2.3 面包屑

- 单页三 Tab：`首页 > 充值中心`（当前 Tab 用页面内标题或 Tab 文案表示，不必塞入面包屑每一层）。
- 若拆路由：`首页 > 充值中心 > 在线充值` 等。

## 三、全局入口与跨页联动

| 入口 | 行为 |
|------|------|
| 侧栏「💰 充值中心」 | 跳转 `/billing`（或默认 Tab） |
| 首页仪表盘（P1） | 卡片展示 **当前余额（USD）** + 主按钮「充值」→ 同上；次要链结「查看流水」→ `/billing` 并选中「消费记录」Tab |
| API 调用失败（余额不足） | 错误提示文案含 **去充值** 链结，指向 `/billing` 或 `?tab=top-up` |
| 消费记录 — 某行关联 `request_id`（P1） | **查看请求** → 跳转 `/logs/{requestId}`（与 [日志中心](log-center.md) 一致） |

## 四、在线充值 Tab（P0）

### 4.1 页面结构（桌面）

```
┌─────────────────────────────────────────────────────────────────────────┐
│  摘要区（可随 Tab 常驻页顶）                                                │
│  当前余额   $ 1,234.56 USD          （可选）最近一笔充值 / 今日消费摘要      │
├─────────────────────────────────────────────────────────────────────────┤
│  快捷金额：[ $10 ] [ $25 ] [ $50 ] [ $100 ]   或 运营配置的档位            │
│  自定义金额：[________] USD    （最小 $10，步进 0.01，校验见 §4.3）          │
│  说明文案：最低充值 $10 · 到账时间以支付渠道为准 · 货币为 USD              │
│  [ 确认并前往支付 ]   （主按钮；未满足校验时 disabled）                     │
├─────────────────────────────────────────────────────────────────────────┤
│  次要：支付方式说明 / 安全提示 / 链结「充值记录」Tab                       │
└─────────────────────────────────────────────────────────────────────────┘
```

**交互要点：**

- 点击快捷金额：填入自定义输入框并**高亮对应 Chip**；再次点击同一 Chip 可保持选中。
- 自定义输入与 Chip **双向同步**：手动输入非档位金额时，Chip 全部取消选中。
- **主按钮**：触发创建订单并跳转第三方支付页（或弹层内嵌）；跳转前 **二次展示**「充值金额：$X.XX USD」确认（可用底部 Sheet 或对话框，避免误付）。

### 4.2 支付返回

| 场景 | 界面反馈 |
|------|----------|
| 成功 | 回到控制台 `/billing`，顶部 **成功 Toast**：「充值已提交，到账后余额将更新」；若 webhook 实时到账，可 Toast「到账成功」并 **刷新余额**（见 §8）。 |
| 取消 / 关闭支付页 | 返回 `/billing`，**中性 Toast**：「未完成支付」；不修改余额。 |
| 支付渠道失败 | **错误 Toast**，保留已填金额，允许重试。 |
| 长时间 Pending | 充值记录列表中该笔为「处理中」；可选轮询或用户手动刷新（P1）。 |

### 4.3 校验规则（前端）

| 规则 | 说明 |
|------|------|
| 最低金额 | ≥ 产品配置的最低充值（与 [功能详解](../../product/features.md)、产品方案一致，如 **$10 USD**） |
| 精度 | 最多 2 位小数；输入非法字符过滤 |
| 空值 | 主按钮 disabled |

## 五、消费记录 Tab（P0）

### 5.1 页面结构

```
┌─────────────────────────────────────────────────────────────────────────┐
│  时间范围 · 模型（可选）· [查询] [重置]                    [导出 CSV] P1   │
├─────────────────────────────────────────────────────────────────────────┤
│  表格：时间 · 类型（扣费/调整）· 模型 · 金额(USD) · 余额后 · 关联请求      │
├─────────────────────────────────────────────────────────────────────────┤
│  分页                                                                     │
└─────────────────────────────────────────────────────────────────────────┘
```

### 5.2 表格列（默认）

| 列 | 说明 |
|----|------|
| 时间 | 本地化日期时间；默认倒序 |
| 类型 | 文案：「模型调用扣费」等；调整类单独标识 |
| 模型 | `model` id；无则 `—` |
| 金额 | **−$X.XX** 用减号与语义色（勿仅依赖颜色）；退款/回补为正或单独类型 |
| 余额后 | 该笔入账后的可用余额（USD）；无则 `—` |
| 关联请求 | `request_id` 短显 + 复制；P1 增加「查看请求」→ 日志详情 |

### 5.3 空态

- 文案：**暂无消费记录**；说明「产生模型调用并成功扣费后，将在此展示。」
- 主按钮：**去充值** 或 **查看 API 密钥**（按产品偏好二选一或并列次要链结）。

### 5.4 URL 状态（可选）

- 筛选条件写入 Query，与 [日志中心 — URL 与状态同步](log-center.md) 原则一致，便于分享与刷新。

## 六、充值记录 Tab（P0）

### 6.1 表格列（默认）

| 列 | 说明 |
|----|------|
| 时间 | 创建/支付完成时间（以后端为准） |
| 金额 | **+$X.XX USD** |
| 渠道 | 如 Card、PayPal 等展示名 |
| 状态 | Badge：**成功** / **处理中** / **失败**；色弱场景配图标或文字 |
| 外部单号 | 可复制；过长省略 + Tooltip |

### 6.2 行交互

- 失败行：**重试** 或 **联系支持**（链结）由产品定；P0 可仅展示状态与说明文案。

### 6.3 空态

- 文案：**暂无充值记录**；主按钮引导至「在线充值」Tab。

## 七、金额与格式（USD）

| 项目 | 规范 |
|------|------|
| 展示 | 前缀 `$`，千分位分隔，保留 2 位小数，后缀文案 **USD**（首屏摘要可写「账户余额 · USD」） |
| 正负 | 消费为负向语义（「−$0.12」）；充值为正向（「+$10.00」） |
| 对齐 | 表格内金额**右对齐**，表头与数字等宽字体可选 |

与 [设计令牌](design-tokens.md) 中的字体层级一致；货币符号与数字之间无多余空格或统一为一种风格。

## 八、反馈与可感知性

| 场景 | 反馈 |
|------|------|
| 余额变更 | 充值成功或 websocket/轮询更新后，摘要区数字 **更新**；可选短暂高亮动画（≤300ms，尊重 `prefers-reduced-motion`） |
| 提交支付 | 主按钮 **Loading** 禁用连点 |
| 列表加载 | 表格 Skeleton；错误时 **行内错误状态** + 重试 |

---

## 九、无障碍与文案

- **快捷金额**与**自定义输入**使用 `aria` 与可见 Label（如「充值金额（USD）」）；勿仅用占位符代替标签。
- 错误与成功提示：除 Toast 外，关键失败可用 **Alert** 区域确保读屏可读。
- 状态 Badge：**处理中** 附带说明「到账可能延迟数分钟」，避免用户重复支付。

## 十、移动端

与 [移动端设计](mobile.md) 一致：

- Tab 可横向滚动或使用 **分段控件**；摘要区余额字号略大便于扫视。
- 充值页主按钮 **吸底**（safe area）；快捷金额 Chip 换行排列。
- 表格在窄屏改为 **卡片列表**（每笔一张卡，核心字段：时间、金额、状态/模型）。

## 十一、验收清单（交互）

- [ ] 侧栏可进入充值中心，三 Tab 可切换且无死链。  
- [ ] 在线充值：快捷金额、自定义、最低金额校验、前往支付前确认。  
- [ ] 支付返回成功/取消/失败均有对应反馈，余额仅在成功到账规则满足时更新。  
- [ ] 消费记录、充值记录空态与加载态齐全；金额格式符合 §7。  
- [ ] （P1）消费记录可跳转至对应请求日志详情。
