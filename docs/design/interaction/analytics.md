## 一、目标与定位

### 1.1 用户价值

在**可配置时间范围**内，以图表与 KPI 展示网关的**用量、结构与成本（可选）**，支撑排障、容量与成本感知；与**日志中心**形成「先看趋势 → 再下钻单条请求」的闭环。

### 1.2 与首页（仪表盘）的分工

| 区域 | 首页 `/` | 统计分析 `/analytics` |
|------|----------|------------------------|
| 时间维度 | 以「今日」等短周期概览为主（实现阶段可配置） | **用户自选**时间范围（如近 24h / 7d / 30d、自定义） |
| 深度 | 少量 KPI 卡片 + 后续可接迷你趋势 | **多图表白、分布、趋势**；可对接导出（分期） |
| 典型用户 | 快速健康检查 | 分析用量结构、排查异常集中时段/模型 |

避免两页重复同一套大图表；首页保持轻量，统计分析承担「可筛选、可对比、可下钻」。

## 二、范围与分期

| 分期 | 内容 | 说明 |
|------|------|------|
| **P0（初版）** | 全局筛选 + KPI 摘要；**请求量 / Token 趋势**（按时间桶）；**按模型**的分布；**按 HTTP 状态或成败**的概览（若后端能提供桶聚合） | 与 [前端开发计划 3.8](../../development/frontend-development-plan.md)「模型分布、成本分布」对齐；**成本/金额**仅在具备定价与聚合接口时纳入，否则以 **Token** 代理成本意图 |
| **P1** | **按 API 密钥**（及可选 **应用**）分布；**延迟**（如 P95）趋势；从图表**跳转日志中心**并携带筛选 query；**报表导出**（CSV 或与现有日志导出一致的异步任务） | 依赖统计类 API 扩展；交互见 [第六节](#六与日志中心的联动) |
| **P2** | 按部门/项目分摊、同比/环比、用量预警配置与通知 | 与 [功能详解 4.1–4.2](../../product/features.md#四统计分析功能) 中长期能力一致，不阻塞 P0 |

**不在本文 P0 范围内：** 复杂 BI、自定义看板拖拽、实时秒级大屏（产品可另立项）。

**数据延迟：** 与产品规格一致，聚合结果相对实时数据可接受 **&lt; 5 分钟** 级延迟（以后端实际为准）；页面需可读提示。

## 三、路由、鉴权与权限模型

| 路径 | 页面 | 鉴权（当前实现） |
|------|------|------------------|
| `/analytics` | 统计分析 | 需登录（`AuthGuard`） |

**建议的数据权限（由后端强制，前端仅展示可用筛选项）：**

| 角色 | 可见数据范围 | 说明 |
|------|----------------|------|
| 普通用户 | 仅本人产生的请求统计 | 用户、全量租户等筛选项不展示 |
| 普通管理员 / 超级管理员 | 可扩展为按用户、全租户 | 具体以 OpenAPI 与 RBAC 为准 |

> **说明：** 控制台路由是否对 `/analytics` 套用 `AdminGuard` 属**产品决策**：若仅管理员看统计，则路由与侧栏应对齐隐藏或守卫；若全员可看「自己的统计」，则保持登录即可。实现前须在本文档与 `frontend/src/routes/index.tsx` 中统一。

## 四、页面信息架构

### 4.1 单页 + 次级分区（推荐初版）

初版采用**单页纵向滚动**，顶部为**全局筛选**，下方为固定顺序的区块，降低路由与状态复杂度。图表较多时再考虑 Tab（如「用量 / 结构 / 成本」）。

```
统计分析
├── 页头：标题 + [刷新]（按当前筛选重拉数据）
├── 全局筛选条（见 4.2）
├── 区块 A：KPI 摘要卡片（4～6 个）
├── 区块 B：趋势图（请求数、Token；P1 加延迟/错误率）
├── 区块 C：结构分布（模型；P1 加 API 密钥/应用）
└── 区块 D：成本相关图（仅在有金额聚合接口时展示，否则隐藏或「即将推出」）
```

### 4.2 全局筛选条

与 [日志中心](log-center.md) 的习惯保持一致，降低学习成本。

| 控件 | 行为 | P0 |
|------|------|----|
| **时间范围** | 快捷：近 24 小时 / 近 7 天 / 近 30 天 / 自定义起止 | ✓ |
| **模型** | 可搜索多选 | ✓（选项来自统计接口元数据或枚举） |
| **API 密钥** | 可搜索多选 | P1（P0 可「全部」） |
| **用户** | 可搜索 | 仅管理员；普通用户不出现 |
| **应用（App）** | 与日志中心一致 | 有维度则展示，否则隐藏 |

操作：`[查询]` / `[重置]`；切换筛选后图表进入 loading，失败时 Toast + 区块级错误提示。

### 4.3 桌面端线框（P0）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 统计分析                                              [刷新]              │
├──────────────────────────────────────────────────────────────────────────┤
│ 时间范围 [近7天 ▼]  模型 [全部 ▼]  [查询] [重置]                           │
├──────────────────────────────────────────────────────────────────────────┤
│  [总请求]     [成功率]      [总 Token]      [估算成本*]   (*视接口而定)    │
├──────────────────────────────────────────────────────────────────────────┤
│  趋势：请求数 / Token（双轴或分图，以后端桶粒度为准）                        │
├──────────────────────────────────────────────────────────────────────────┤
│  分布：按模型（条形图或饼图；长尾可合并为「其他」）                           │
└──────────────────────────────────────────────────────────────────────────┘
```

## 五、区块规格摘要

### 5.1 KPI 卡片

建议指标（以后端可用字段为准）：

- 时间范围内的 **总请求数**、**成功请求占比或 2xx 占比**、**总 Token（prompt+completion）**、**估算成本**（可选）、**平均或 P95 延迟**（P1）。

每张卡片可带相对上一周期的**环比文字**（P1；需后端支持对比桶）。

### 5.2 趋势图

- X 轴：时间桶（如小时/天，由范围与后端约定自动粒度）。
- 系列：至少 **请求数**、**Token**；系列过多时用图例切换可见性。

### 5.3 分布图

- **P0：** 按 **模型** 的占比或 Top N + 其他。
- **P1：** 按 **API 密钥**、**应用**；可与日志列表相同的标识展示规则。

### 5.4 空状态与边界

- **无请求数据：** 说明「产生请求后一段时间内可见统计」；可提供跳转 **创建 API 密钥** 或 **文档** 的链接（可选）。
- **范围过大：** 由后端限制最大区间或降采样；前端提示用户缩小范围。
- **加载与错误：** 骨架屏 + 区块级重试；禁止静默失败。

## 六、与日志中心的联动

**P1 能力：** 在趋势图某一时间桶、或分布图某一模型/密钥上提供「查看日志」操作，跳转 `GET /logs` 列表并预填：

- 时间范围对齐所选桶或保持全局范围；
- 模型、API 密钥等维度的筛选与列表接口一致。

参数命名与 [日志中心](log-center.md) 筛选 query 对齐，避免两套约定。

---

## 七、前端实现要点（非 exhaustive）

- **图表库：** 与 [前端架构](../../architecture/frontend-architecture.md) 规划一致，**按路由懒加载**图表依赖，仅进入 `/analytics` 时加载。
- **无障碍：** 颜色对比度、图表附**数据表格摘要**或可读标签（供屏幕阅读器与精确读数）。
- **主题：** 使用现有 design tokens，深/浅色下图表配色可随主题切换（实现阶段细化）。

## 八、后端与契约依赖

当前联调清单见 [前端开发计划 5.2](../../development/frontend-development-plan.md)：**统计分析接口（overview / usage / models 等）** 为 P0 前置。建议约定：

- 所有图表共用一套 **query 参数**（时间、模型、密钥、用户等）与 **统一错误格式**。
- 响应为 **服务端聚合**，前端不对原始请求日志做全量拉取画图。

OpenAPI 定稿后，在本节增补具体路径与字段表（或链接到 `development/api.md`）。
